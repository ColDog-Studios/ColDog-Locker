# Launch remediation

Scope: every finding F01–F23 and the remaining launch-validation requirements in [the original review](launch-review.md). The review is a historical snapshot; this file tracks current implementation and verification. A code change alone does not close a platform-validation requirement.

Current finding count: **20 of 23 implemented and validated; 3 remaining** (all in progress). Progress updates should include these counts and distinguish partial work from completed findings. Signing remains deferred.

## Compatibility decision

The user explicitly permits breaking changes and does not require backward compatibility because the application has no stable release (2026-09-21). Legacy archive readers, password-verifier compatibility and database migrations are not launch requirements. Prefer a simpler current-format implementation where removing compatibility improves correctness or security; document intentional format/schema changes. Existing compatibility code has not all been removed yet. This decision does not weaken current-version round-trip, failure-preservation or recovery requirements.

## Work order

1. Formatting/cleanup, test environment, channel policy, stateless CLI commands, updater timeouts, locked metadata edits.
2. Path validation, password semantics, archive limits, persistence consistency, GUI work, package dependencies and reproducibility.
3. Archive metadata/security, transaction ownership, crash recovery, source consistency, recovery/import and backup workflows.
4. Installed-artifact/platform validation, signing/provenance, accessibility, documentation and final regression audit.
